## 三、问题清单

### P0（实现必改，否则功能不生效）

**P0-1 · fragment 的 `data-*` 配置属性缺 `th:` 前缀（方案 §4，L122-127）**
- 问题：`data-title="${theme.config.heatmap?.title ?: '写作热力图'}"` 等 4 个属性是普通 HTML 属性，Thymeleaf 标准方言**只处理 `th:*` 属性与 inline 表达式**，不处理属性值里的裸 `${...}` → 服务端渲染后原样输出字面量，JS `container.dataset` 读到的是模板字符串本身，title/range/clickable/showStats 四个配置**全部透传失败**。
- 证据：全仓无「非 th 属性内直接写 `${`」先例；data-* 注入的统一先例是 `th:attr`（`archives.html` L129 `th:attr="data-api=..."`、L153 `th:attr="data-comment-count=..."`）。
- 修正：改用单个 `th:attr` 合并赋值，并删除 §4 中「inline 静态回退」的错误说明（CLAUDE.md 的 `/*[[${...}]]*/ 默认值` 静态回退仅适用于 JS inline，不适用于属性）。

**P0-2 · `th:if` 与 `th:replace` 放同一 `<th:block>`，开关失效（方案 §7，L340-344）**
- 问题：Thymeleaf 属性优先级表中 **Fragment inclusion（th:replace）为第 1 级、Conditional（th:if）为第 3 级**，同一元素上 `th:replace` 先执行把元素整体替换掉，`th:if` 永远不会被求值 → **开关关闭时热力图依然渲染**，直接违背方案验证项「开关关闭时零残留」。
- 证据：Thymeleaf 官方教程「Attribute Precedence」优先级表；社区一致结论（StackOverflow："th:replace replaces the div element before computing the if condition that was on it"）；全仓无同元素组合先例，仓库做法是嵌套 `<th:block th:if>` 包裹。
- 修正：两层嵌套——外层 `th:if`，内层 `th:replace`（`~{modules/heatmap :: heatmap}`）。

### P1（必须修正）

**P1-1 · 归档链接 month 必须两位（方案 §6.4 L302、§10 验证项）**
- `/archives/{year}/{month}` 中 month 正则 `\d{2}`，`/archives/2026/1` → 404。JS 生成 href 时 month 需 `padStart(2,'0')`；验证清单「点击格子跳转 `/archives/2026/1` 正常」改为 `/archives/2026/01`。

**P1-2 · CSS 变量名不存在（方案 §5.2 L164-165、§5.4 L196）**
- `--card-bg`、`--border-color`、`--text-secondary` 全仓 **0 命中**，引用后 `background`/`border-color` 解析为无效值（透明），标签色回退默认。
- 真实变量：`.archive-card` 用 `var(--color-bg-soft)`（archives.css L83）、`var(--color-border)`（L84）、`var(--radius-lg)`（L85）；次级文字色为 `--color-text-secondary`（base.css L17）。
- 修正：改用 `--color-bg-soft`、`--color-border`、`--color-text-secondary`。

**P1-3 · 暗色模式方向与主题机制相反（方案 §5.1 L150-157）**
- 主题机制：**暗色为基**——`:root` 全部暗色值（base.css L9-56），`[data-theme="light"]` 覆盖亮色（L161-177），组件惯例 `[data-theme="light"] .archive-card`（archives.css L117）；`data-theme` 挂在 `<html>`（layout.html L15）。
- 方案写「`.heatmap-card` 默认亮色 + `[data-theme="dark"]` 覆盖暗色」反向。正常加载时 `data-theme` 恒被设为 dark/light，反向写法**碰巧能对上色**；但 head 内联脚本未执行（CSP 拦截 / noscript / 静态预览）时 `data-theme` 缺失 → 页面按 `:root` 渲染暗色、卡片却按默认亮色渲染 → 暗色页面出现亮色卡片。
- 修正：`.heatmap-card` 默认写暗色值，`[data-theme="light"] .heatmap-card` 写亮色值（跟随主题主导机制）。

**P1-4 · tooltip 首行被滚动容器裁剪（方案 §5.3 L176-177 + §5.5 L202-215）**
- `.heatmap-grid{overflow-x:auto}` 时 `overflow-y` 的 used value 也变为 `auto`（两轴裁剪）；首行格子 tooltip 用 `bottom:calc(100%+6px)` 向上弹出约 22-24px，超出容器顶部（仅 8px padding）被裁掉一大截。
- 修正：首行格子（列优先排布即第 1/8/15… 个，`.heatmap-cell:nth-child(7n+1):hover::after`）把 tooltip 翻转到下方（`top:calc(100%+6px); bottom:auto`）；或将月份标签行并入同一滚动容器并给足高度；**不要在 `.heatmap-card` 上设 `overflow:hidden`**（`.archive-card` 的 `overflow:hidden` 先例若照抄同样会裁）。

**P1-5 · 首次加载时同步调用 `bindPageEvent` 会 ReferenceError（方案 §6.5、§8）**
- content 内脚本（`archives.html` L22-24，位于 `#pjax-main`）**先于** layout 底部 `main.js`（`layout.html` L577）执行 → 首次整页加载时 `bindPageEvent`（main.js 全局函数）尚未定义，若 `init` 在脚本加载时同步调用即 ReferenceError，组件整体中断；PJAX 下 main.js 常驻反而正常 → 首载与 PJAX 行为不一致。
- 修正：`bindPageEvent` 的调用**只在异步回调中**（`fetchAllPosts().then` → `render` 内，此时 main.js 必已执行），并在 `init` 内加 `typeof window.__bindPageEvent === 'function'` 守卫。

**P1-6 · CSS/JS 无条件引入与「开关关闭零残留」验证自相矛盾（方案 §7 L338/347 + §10 L384）**
- `<link heatmap.css>` 与 `<script heatmap.js>` 均无 `th:if` 门控，开关关闭时浏览器仍请求这 2 个资源，验证项「配置开关关闭时页面零残留（无请求、无 DOM）」按现状实现**无法通过**。
- 修正：三处（CSS link、JS script、fragment replace）统一套 `th:if="${theme.config.heatmap?.enabled == true}"`（link/script 上 `th:if` 与 `th:href`/`th:src` 组合合法，先例 `about.html` L14/L38-40）；或把验证口径改为「无数据请求、无 DOM」。

**P1-7 · 验证清单缺后台配置侧验收（方案 §10）**
- 清单 14 项全部是前台效果类，无「第 17 组表单能否渲染、`$get(heatmap_enabled)` 联动、默认值、保存后前台生效」验收——若 FormKit schema 引用有误前台直接不可达，清单无法发现。
- 修正：补后台验收项（详见第五节）。
